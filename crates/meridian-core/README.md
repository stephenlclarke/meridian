## Pure docking geometry

The `docking` module uses explicit `f64` column bases, poses, port polygons and borrowed mesh data. It has no World, station ID, command, GPU, filesystem, clock or save dependency. `StationPose::entrance_frame` applies local +Z station roll before the column orientation. `EntranceFrame::assess` reports geometry predicates and projected coordinates; neither result admits docking or creates a receipt. Inputs use the same native model/reference frame as the caller's admitted data, with no implicit scale conversion or bridge to the flight shell's `f32` snapshot.

| Primitive | Preserved reference rule |
| --- | --- |
| Entrance region | Player is strictly behind the entrance plane; absolute projections on model X, entrance up and model Z are each below90 |
| Point entry gate | Absolute lateral below25, vertical below8, depth at most1 and strictly above-25; outward Z below-0.98; absolute roll phase below0.1; speed below144; spin error below0.1 or absolute roll below0.15 |
| Aligned aperture fit | Every mesh vertex is strictly more than the nonnegative margin inside every counterclockwise convex polygon edge, in port-local x/y |
| Transformed aperture fit | Transform every whole-mesh vertex through player pose, station dot/transpose coordinates and port-center subtraction before the same strict half-plane test |
| Native approach geometry | Mesh maximum vertex radius plus400, then another1000 for approach distance; approach point is entrance position plus outward times explicit distance |

The entry gate deliberately retains the reference's finite scalar comparison, including its absence of a lower speed bound. The caller must supply actual valid relative motion. The aperture projection does not constrain longitudinal extent, sweep against station triangles, establish a safe route or test other actors. It cannot authorize launch, contact, arrival, paid services, freight receiving or save publication. Prototype navigation rings remain fixtures.

Port validation preserves3–64 planar vertices, strict convex counterclockwise edges, the1e-8 unit/orthogonality tolerance and source coordinate bound1e12. Mesh checks preserve source vertex/face/index requirements; these are not a watertight-solid proof. Basis validation uses the original strict1e-4 length/dot tolerance without normalization or a new determinant rule. Its dot/transpose operation is the source operation for admitted near-orthogonal bases, not a general matrix inverse. Non-finite input and computed geometry refuse through typed errors or a failed clearance predicate; approach distance and clearance margin must be finite/nonnegative. No malformed-input path grants docking.

## Original station launch and docking loop

`World::at_original_station()` creates the explicit initial dock context with byte-exact imported SH028 Lion Citadel and SH025 native hull data. It does not infer arrival from a rendered ring or an arbitrary position. `OriginalStationData::from_bytes` accepts only the exact packaged native mesh/port bytes; `World::at_station` lets the host supply this validated binding. `Snapshot.mode` is Docked, Launching or Flight, and `Snapshot.station` supplies the immutable original station pose to presentation. No flight body/bay location is asserted while initially docked.

`request_launch(current_tick)` rejects stale or duplicate/wrong-mode commands. It computes the real station support minus the actual hull rear plus1000, rounds outward to the f32 flight pose, verifies the whole hull and outward path, then publishes Launching at source speed8. The next normal tick becomes Flight. The original station source spin rate is0. Station-scene translation uses game speed×18 from the native source; existing free-flight prototype tests keep their original scale and speed/acceleration/control rules.

Entry is automatic through public flight inputs/ticks. It needs an actual positive-to-nonpositive crossing inside the authored aperture, physical speed below144, forward/outward dot below-0.995, up/up dot above0.995, matched roll below0.1, exact whole-hull aperture checks and continuous station clearance. Proximity, a key, a descriptive snapshot or merely crossing the infinite port plane cannot dock. The normal flight constructor accepts only validated initial poses outside the port with a clear hull; it is not a command to teleport an existing World.

Continuous clearance conservatively sweeps an AABB containing the entire native hull against all488 native station triangles. It bounds intermediate rotation by hull radius×total angular travel plus numerical inflation, rejects understated rotation, and uses continuous SAT time intervals rather than endpoint sampling. It may stop some physically clear courses. A contact/unsafe entry is an accepted conservative stop: retain the last clear position/orientation, speed0, mode Flight, tick advance and `Snapshot.motion_refusal`. This lets the pilot recover; it is not full source damage/impulse/sliding parity. Invalid inputs/state and rejected stale commands remain transactional errors with unchanged state.

The original display has5888 vertices/10056 triangles; the collision LOD has272 vertices/488 triangles and is explicitly not full display-surface equivalence. The SH025 physical hull has536 vertices/964 triangles. Import provenance, exact port data and source calibration limits are in `assets/legacy/station-manifest.json`. This is an isolated original station scenario: other actors/celestials, fitted hull attachments, systems/travel, source/owner/visit arrival authority, paid services, freight integration and save/receipts remain separate requirements. World still owns all mutable state; snapshots and render data grant none of that authority.
