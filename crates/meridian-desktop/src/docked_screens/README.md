# Docked screens

Author-stage desktop presentation for Galactic Chart, System Data, Ship Showroom, Market and Equip Ship. This leaf module is based on committed Meridian `8da5d64f9e8c9425b3cae120abfb723fab3ae50e`. It changes no App, profile, World, renderer, HUD, Cargo manifest, lockfile or save format. Root must register and connect it before it appears in the game. The authored Rust tests, compilation, Clippy, coverage, native input/rendering and visual acceptance remain **UNRUN**.

The human chose a greenfield Meridian interface. L337's owned content, visual direction and intended capabilities are references; its old keyboard letters, menu structure, save readers and internal architecture are not compatibility requirements. The module uses five consistent tabs, a live commander summary, scrollable selection/details, pointer hit regions, and the same semantic actions for mouse and keyboard. Black, yellow, cyan, blue and category colours retain the original palette. No copied classic Elite/Oolite model, texture or image is included.

## Data and authority

[SOURCE.json](SOURCE.json) binds 197 immutable source files at L337 `a11fe16924d87d06021816f9037952afcbac08db`, tree `68fec574df12ddf74acb14747e0dd6839f478642`. It includes the complete original world catalogue and all authored R3 object definitions. The embedded display data contains 2,048 normal worlds, 162 ships, and nine separately classified objects: six stations, one capsule, one platform and one other object. It does not call 171 mixed objects 171 ships. Hidden PLUGH worlds are not imported or revealed. The exact original MIT notice is retained in [ORIGINAL-L337-MIT.txt](ORIGINAL-L337-MIT.txt).

The showroom lists every authored ship, searches names/families/roles/IDs, and displays standard reference specifications, accommodation, fitting and geometry notes. Authored estimates and catalogue presence do not establish current fitting, ownership, stock, physical admission or purchase permission. The comparison uses standard reference profiles; the commander summary and equipment view use current World/provider values. Actual live fitted ship comparison can be added by Root/G4 through their real projection, without relabelling reference statistics as live ones.

Only actual provider handles produce ship or planet preview requests. Missing meshes produce a visible unavailable preview, never a replacement model. Both showroom model requests carry exactly the same pitch/roll/yaw orientation. Drag controls pitch/yaw; a roll-modified drag controls roll. Axis selection, signed turns, reset and rotation pause operate on the same presentation orientation. G1 resolves geometry keys through its approved original asset registry; they are logical handles, not permission to load arbitrary files.

The chart preserves original Cartesian light-year coordinates, including valid negative coordinates. All eight normal galaxies can be inspected. World selection does not move the commander. Root supplies fitted/current reach and the actual supported route targets; unsupported systems remain reference data. Galaxy inspection cannot grant cross-galaxy travel. The actual current World provides cash, market asks/bids, finite commodity stock, native units, cargo and reserved cargo. A displayed row never creates a quote or transaction.

## Root connection

Add `mod docked_screens;` to the desktop entry point during the serial join. Construct `Catalogue::bundled()` once in the host's immutable content cache. Construct `DockedScreens::new(actual_system, actual_hull)` when opening the station UI. Neither construction changes a commander or reads a profile. Keep the module's local filter, selection, scroll and model orientation out of simulation ownership; no legacy UI-state migration is required.

Build `Context` from the latest authoritative state and actual providers. `world` is borrowed immutably. `current_hull`, reach, route targets, model handles, exchange offers, modular equipment and navigation bodies must come from their real owners. Do not fill unavailable data with synthetic offers, placeholder stock or adopted hulls. `planet_previews` means the real G1 planet provider is connected; its output carries the selected original system ID and a bounded display area.

`Viewport` and all label, hit and preview bounds use logical window points. Root converts winit pointer coordinates using the same scale factor as G1's frame composition. G1 draws the supplied labels, clipped lines, category markers, range rings and model/planet requests. Every `Marker.clip` is the actual `ChartLayout.plot`; clip its circle and current/selection decorations to that rectangle even when its centre is inside the plot. This module creates no GPU resource and imports no renderer code. Render a black menu background and preserve each primitive's clip; do not squeeze the existing flight HUD beneath a full station page. `Frame.hovered` identifies the actual hover region. `Frame.search_active` gives the text-input adapter focus ownership.

Pass the **last actually presented** `Frame` to `handle`. A stale session, material/UI revision, screen or selection refuses without emitting an action. Root owns `Stamp`: change it when the commander, berth, fitting, inventory, market, modal review or action-relevant projection changes. Cosmetic redraw ticks need not pretend the material state changed. Every processed selection/action invalidates the old UI frame; reproject before the next actionable event. While a station menu owns focus, `Ignored` means no local action; it must not fall through into flight/fire/launch shortcuts. Root clears held flight input when entering menus or losing focus. A focus-loss event cancels text editing and pauses preview rotation.

Root owns the binding map. Translate physical keys into `Key`, typed text into `Input::Text`, and mouse movement/click/scroll/drag into the corresponding input variants. Supply `BindingHint` labels from the **same active binding map**; the module does not advertise old letters or invent shortcuts. Page keys scroll chart/system facts. Showroom detail focus scrolls specifications; equipment detail focus scrolls readouts. Other list navigation retains the selected identity. Text entry consumes navigation until accepted or cancelled. Back closes options, then details, then the station UI. A pending review owns all hits and confirmation/cancellation input, preventing click-through.

`Outcome::Updated` means presentation state changed, **not** that a transaction committed. `Outcome::Refused` must be shown as feedback. Requests are intent to review actual state:

| Request | Root action |
| --- | --- |
| `Close` | Close the station interface, without launching, quitting or resetting a commander |
| `ReviewRoute` | Ask the actual navigation owner to review the selected supported system |
| `ReviewBodyRoute` | Resolve the actual provider's `(system, ordinal)` body identity and review navigation to its physical position |
| `ReviewCommodity` | Review one native ordinary-market buy/sell using the actual selected `CommodityId` |
| `InspectEquipmentSlot` | Reproject equipment for that real slot; no purchase or fitting effect |
| `ReviewEquipment` | Resolve the actual node, owned instance and destination slot; obtain a real buy/fit/store/configuration review |
| `ReviewShipExchange` | Obtain a real admitted hull/ownership/exchange proposal; source flyability is insufficient |
| `ConfirmReview` / `CancelReview` | Resolve the Root-owned review token, revalidate current material state, then confirm or discard that proposal |

Root publishes the exact prepared save durably before committing the actual World/Profile transaction. Writer failure preserves money, cargo, items, fitting and prior save. The UI contains no second wallet, inventory, stock counter, hull ownership or transaction implementation. Do not turn the UI's request, price, eligibility boolean or review token into a new authorisation source. Root's current paid-missile `AmmunitionAction::Purchase/Store/Refit` is one concrete adapter target; its item/pylon identities and prepared publication remain authoritative.

## Modular equipment contract

`EquipmentPanel` is the current G3 projection for its `selected_slot`. It supplies actual slots and installed names, ordered shop/owned-item rows, current equipment-unit and utility-mount usage, operating crew and transaction feedback. Populate the full authored laser, missile, EMP, navigation, energy, shield, targeting, work, rescue and other equipment capabilities as their actual core support lands. Do not call a cargo-bay-only panel or disabled equipment placeholder completed modular functionality.

Each row identifies an actual node and, when an owned item is selected, its actual instance. Multiple independently owned instances may have separate rows with distinct identities and names; the UI must not deduplicate them into a fictitious interchangeable item. `owned` and `fitted` are current projection counts. Row readouts and configurable options come from the same component statistics consumed by mechanics. Compatibility, prices, option values, action availability and refusal reasons are supplied by the core projection.

Buy emits no pre-existing instance identity. Fit/store/configuration retain the selected real instance and slot. The host maps these opaque identities back to actual domain handles, including ownership and revision checks. Switching slots asks Root to reproject the panel; it never silently reinterprets an old quote for a new slot. The actual component owner chooses replacement/storage rules, capacity consequences and genuine effects. Confirmation must update the provider's fitted statistics/readout and feedback after durable success; cancellation and publication failure must not update them optimistically.

`OfferQuantity::NotTracked` deliberately draws no stock count. Original Missile shops have no mutable finite station quantity. Do not synthesise a zero counter, decrement a made-up shop balance, or mistake pylon/ownership/purchase limits for shop stock. `Available(n)` is for an actual authoritative quantity counter when one exists.

The projection fixtures in the Rust tests are labelled fixtures. They test UI dataflow and identity handling, and are not a live inventory, price catalogue or proof that G3 mechanics work.

## Belt navigation and later notice board

`NavigationBody` carries the actual provider's stable `(system, ordinal)` identity, name, **station-local World/renderer position**, optional measured distance, target availability and refusal. It has no duplicated mesh, ore quantity, depletion store or independently invented marker position. Real supplied bodies appear in System Data as navigable entries with keyboard and pointer paths. `Frame.navigation_cues` retains the same exact identity/position for Root/G1. No provider means no invented belt entry. Exhausted asteroids remain physical if the provider retains them; this UI never removes them because ore was depleted.

MC1's concrete next provider is an authored Avenor local ore-belt segment in the same World/renderer frame. Root resolves navigation and G1 uses the provider's physical/render position. A catalogue planet-ring flag is not evidence of an asteroid belt. Actual reachability, mining admission, commodity extraction, travel/save depletion and cargo accounting remain MC1/Root mechanics and require their own qualification.

A station Most Wanted board follows as a separate core increment. The concrete tab/frame/action composition can gain that screen when Root supplies real bounty, target identity, tracking and claim state. No wanted list, rank, reward, target or payout is fabricated here, and that later board does not block the first five screens.
