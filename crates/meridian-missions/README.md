# Lua mission controller

This crate ports the original explicit-state Lua boundary and delivers one real native adapter: the original T01 `mission.accepted` callback joined to World's existing opaque flight-reception preparation. It loads the Researcher's sealed original content, executes genuine Lua, validates proposals, stages explicit state/acknowledgement/journal with the native candidate bytes, and publishes the combined envelope before either in-memory commit. It adds no second simulation, wallet, custody graph, T01 flight evidence or reward authority.

Status: implementation and tests are authored. Rust compilation, 139 frozen compatibility invocations, the corpus-integrity test, seven World/controller tests, five publication-preservation tests, Clippy and runtime coverage are **UNRUN** until the existing execution owner runs the identified source. All original 147 tests remain unchanged; the new total is 152. Source formatting, dependency resolution and artifact integrity are separate checks. This is not installed-app or 64-mission acceptance.

## Runtime contract

`Pack::bundled_flight_reception()` selects only `l337.training/flight-reception@1.0.0`, verifies the content record, parses the exact original manifest and reconstructs the original ScriptWire-framed digest `bc01834e04f87816c8021b76fabe3d9b8f3af394ff8fcd420c4b7c3acf1350d4`. Namespace alone is not an identity. Missing, changed, incompatible or unsupported content refuses; saved state retains definition/version/digest and suspends when the exact content is unavailable. Resume is explicit and requires the same identity and supported requirements.

Each evaluator operation creates a fresh Lua 5.5.1 VM and drops it after conversion. Lua receives only copied `(event, scopedSnapshot, explicitState)` values. The module is compiled as text, must return a handler table, and the selected function must return exactly `data` and `commands`. Data must be a map; commands must be a dense array of at most 256 values, with the original empty-map-to-empty-array compatibility. Only returned explicit data survives; Lua globals, closures, tables, userdata and interpreter handles do not persist.

The sandbox loads base and math only. It removes `_G`, loading/file/printing/collection operations, `pcall`/`xpcall`, metatable/raw traversal functions, `pairs`/`next`, and math RNG, matching `MissionScript.c`. Scalar-only `tostring` remains. The hash seed is the original constant 1. There is no process, filesystem, network, coroutine, debug, package, string or table library, and no Lua callback into gameplay.

| Original source boundary | Retained limit |
| --- | --- |
| Instruction hook | 1,000-instruction quantum; default 50,000; failure when count reaches/exceeds the configured limit; source range 1,000 through 1,000,000 |
| VM heap | Default 8,388,608 bytes; source range 65,536 through 16,777,216 |
| Cumulative allocation requests | Default 33,554,432 bytes; at least heap size and at most 67,108,864; successful realloc charges full new size, including shrink; free gives no refund; failure charges nothing |
| Source/input/output | Source at most 262,144 bytes; aggregate input 1,048,576; default output 524,288, configurable 1 through 1,048,576 |
| Value trees | Depth strictly below 32; at most 16,384 values; dense arrays or string-keyed maps; no mixed/sparse/cyclic/nonserializable output; finite f64 and exact signed i64 |
| Explicit returned data | Original separate 262,144-byte wire check |
| Event dispatch/storage | Queue at most 4,096; frozen prefix at most 64; monotonic native event sequences and acknowledgement; journal at most 512 entries of at most 12,000 UTF-8 bytes |

These are source-specified interpreter/value boundaries, distinct from machine/job resource settings. Nothing here changes CI or machine limits. Output accounting runs before copying large aliased Lua strings into Rust, so repeated references cannot expand beyond the output budget during conversion. Wire encoding sorts map keys and preserves integer/floating tags, negative-zero bits, UTF-8 and embedded NUL strings. The original tagged-value shape also has a strict decoder; it does not import a player profile.

`Instance` retains explicit values, pending event envelopes, revision, acknowledgement, journal and suspension only. `prepare` visits the retained queue head and stages all changes. A failed evaluator, unsupported operation, invalid command or exceeded budget publishes no data/journal/acknowledgement. Missing handlers remove the event without running Lua; acknowledged retained events are discarded without effects. A frozen prefix prevents derived events from being recursively consumed in the same dispatch batch. A preparation cannot commit over changed script state. `prepare_dispatch` stages deterministic faults as suspension-only candidates, retaining old data, pending event and acknowledgement; explicit publication is required, and a failed writer is not retried.

`journal.append` is a typed descriptive proposal. `dialogue.offer` remains an unexecuted typed request and cannot be committed by the storage-only path. Credits, payload, custody, equipment, timer, actor, campaign, clue, reward and all other operations fail explicitly. No permissive or mock native handlers exist. Larger native/resource/board/freight/dialogue pack declarations currently refuse in the semantic loader; their genuine raw Lua can still be used by the separate evaluator parity fixtures. The content registry's pack count is not executable coverage. Closed declared Lua modules are compiled from the original exact prelude, sorted IDs and bounded raw UTF-8 resources, with per-VM cache/cycle/refusal behavior and no filesystem loader. Their raw path-framed bytes enter the digest in original sorted resource-path order; undeclared resources and missing `pack-modules-v2` refuse.

## Actual T01 World path

The caller obtains `FlightReceptionReview` from the current World, then calls `prepare_flight_acceptance`. World revalidates the real commander, fit, berth, pause, tick, service capacity and review identity through its existing provider. The adapter reads the exact prepared native candidate only for the actual T01 ID and immutable berth snapshot. It never steps or retains another World, and it never submits decoded descriptors as native proofs.

The original `accepted` callback does not query additional world fields; it returns its genuine journal and empty explicit data. The adapter supplies only actual available scope fields and keeps absent legacy event context null. The stable descriptive instance string maps the real native owner/ordinal; it is not a Swift UUID migration. The native record remains World's sole acceptance/flight/reception authority. No mission payment, clue, cargo, fit or counter is inferred from Lua data or text.

`PreparedFlightAcceptance` holds exclusive mutable borrows until the host atomically publishes `bytes()`. `publish` commits the native plan and script candidate only after the publisher succeeds, with no fallible operation after publication. Drop or storage refusal leaves both originals unchanged. The new `MMIS0001` envelope binds the existing native World save and `MLST0001` explicit script frame with lengths and SHA-256; cold restore validates both and rejoins the script record to an actual retained T01 ID. Unsupported/corrupt data has no fallback, repair, migration or reset. Root must route this envelope through the owned host storage path before enabling the feature in the app; existing profiles stay separate.

After first acceptance, `serialize_flight_publication(nativeBytes, &instance)` preserves the supplied actual current or prospective native-save bytes and retained script frame exactly. It validates the native save, explicit script state, original T01 identity and real owner/ordinal in retained native attempt history. It executes no callback and grants no native authority. The host must use it for every later ordinary save and prospective market, T04, practice or other native confirmation, then publish before the corresponding native commit. Missing/wrong bindings and invalid native saves refuse. This serializer supports bound instances only. Before the first real acceptance, Root's host retains the fresh unbound instance in memory and uses the explicit native save format; format dispatch must never fall back from a refused mission envelope to native data or a fresh instance.

`prepare_flight_transition` prepares later genuine T01 Accept, Cancel and Receive reviews through the unchanged World provider, holding the same exclusive native/script borrows until publication. Its `PreparedFlightTransition` retains the complete original script state, including suspension and pending events, without rerunning `accepted`, synthesizing lifecycle events or rebinding to a retry. The binding continues to identify the original accepted attempt in native history. A retry can create a new real native attempt while that original binding and once-only journal remain unchanged. Other Lua lifecycle/native event dispatch remains unsupported and unaccepted. `PreparedFlightAcceptance` remains an alias for the common preparation type.

Hosts must apply public `MAX_FLIGHT_PUBLICATION_BYTES` to both bounded reads and atomic writes. Its current value is **33,620,048 bytes**: the existing native-save cap of 65,536 plus the original script-body cap of 33,554,432 plus the script checksum of 32 plus envelope framing/checksum of 48. Both serializer and restore independently enforce contained native/script bounds as well; a large outer envelope cannot bypass either inner codec. Restore rejects an oversized outer publication before hashing or decoding, and rejects oversized declared payloads before invoking their decoders. Checksums, lengths, exact identity and retained native binding share the same refusal contract for serialization and restore. No native or interpreter cap is increased.
