## Separate acceptance and actual plan

`review_navigation_trade(Accept, tick)` reviews actual owned main-berth consent. Confirming creates an unplanned retained instance and occupies one actual service slot; it neither reserves cargo capacity nor buys anything. Back or dropping a prepared confirmation changes nothing.

`Plan { destination, commodity }` is a separate review. The player chooses the different supported destination and stocked legal tonne commodity. Current selected ordinary cargo must be zero. The actual current fit, free one-tonne hold, available credits, immutable original distance, usable fitted drive/navigation and current usable one-way jump fuel must pass. Avenor to Renas is the existing original direct route, with 34 fuel tenths each way. Stock, price, cargo load, hold capacity, current fit/inventory revision, route and planned debit are frozen only on confirmation. The plan reserves one tonne of capacity without creating or buying cargo. It does not reserve credits or promise that a later purchase can use changed fitting/stock.

Reviews bind actual dock, owner/hull, session epoch and the complete checked material-state fingerprint already used by T01, excluding only current simulation tick and its derived envelope checksum. Ordinary docked redraw ticks may pass; expected command tick must still equal the actual current tick and future reviews refuse. Plan confirmation stamps the current tick. Changes in fit, stock, wallet, markets, shared state, view, dock or Continue invalidate the old review. A new plan after stale pre-purchase fitting requires cancellation and a fresh instance; no silent repair occurs.

## Real travel, return and reception

Existing `World::request_jump` and the actual countdown own travel. After purchase, all actual jumps while held or sold are retained. The selected sale requires a genuine selected-destination PhysicalEntry whose visit joins the actual arrival, never a position or proximity test. Ordinary fuel before the plan or after closure stays outside this lesson cost. The original maximum of 64 journeys and 64 fuel purchases is retained; no unrelated execution cap is added.

Reception is separately reviewed at the issuing actual berth after selected sale and a later actual return journey, joined to the current PhysicalEntry receipt. It pays zero tutorial money. ## Cancellation, genuine loss and shared owners

Cancel is separately reviewed at a supported actual main berth on the original carrier. It retains an Abandoned terminal and releases capacity or surviving identified cargo without refunding cash or recreating stock. Fresh acceptance/plan/purchase creates a different original transaction identity; it cannot revive the cancelled history.

The original Swift loss path requires a real escape-pod event that removes the original tonne with the abandoned ship. The current Rust core has no escape-pod/cargo-loss transition. Removing a held tonne from a checksummed save refuses; it never manufactures a loss or success. A future actual escape port must supply its genuine source event before that branch can be offered.
