# Planet and sun shading

This renderer slice translates the frozen L337 planet illumination and sun appearance into WGSL/wgpu. It accepts an immutable scene with actual system/visit/body identities, world positions and radii. It creates no default planet, sun or asteroid belt. The simulation remains the only source of physical movement, heat, collisions, mining and navigation state.

The planet shader uses ocean/coast/land, highland, vegetation, polar ice, cloud opacity and drift, surface haze, day/night illumination, atmospheric rim and cloud-attenuated settlement emission. Four interleaved 256 by 128 maps supply elevation, clouds, city emission and nearby settlement scatter. A validated immutable surface owns its palette and maps; a different immutable surface object triggers an upload even if a caller reuses its body identity. The retained GPU cache holds only one surface. It allocates one fixed 512 KiB map buffer and two fixed uniform buffers. It does not allocate a planet-sized framebuffer or synchronously read the GPU each frame.

Lighting comes from the actual planet-to-sun direction after the same camera transform used for the scene. Displayed sphere normals face the viewer, including front, rear and side views. A missing sun produces the source unlit state rather than a decorative fixed light. The sun has the source yellow inner disc, gold outer disc and two orange/gold corona layers. Reference sRGB palette/image colour is converted once for an sRGB render target, including premultiplied halos, to avoid double gamma conversion. Opaque surfaces write depth; premultiplied atmosphere/corona passes test depth without writing it.

The source sphere/frustum intersection and bounded projection retain visible limbs at screen edges and bound near/interior projections. The WGSL sphere is a continuous camera-facing disc at the physical projected radius; the old intermediate bitmap's 0.47 image-padding scale is not copied. Depth is a sphere-impostor approximation, not an exact off-axis raytrace or a collision mesh. This is a deliberate rendering change, not pixel-equivalence evidence.

## Core-owned scene and safety

`World::celestial_snapshot` now derives the scene from the actual `OriginalNavigation` system, saved visit/tick and station frame. Each planet/sun ID includes galaxy, system, visit and entity. The planet's surface turns once per 72,000 simulation ticks; pause stops that clock, and cold Continue reconstructs the same angle and recipe. Body positions are static in the current station-local world frame. There are no orbital or gravity dynamics.

Placement and scale are new Meridian design choices, not inherited L337 physical acceptance or measured astronomy. The planet is offset by `(6000, -1800, 9500)` world units with a system-seeded X mirror and radius 1800–2200 units. The sun is at `(-8500, 4400, 14500)` with the same mirror and radius 1300. Both are clear of the current birth/launch corridor in all 256 systems currently supplied by OriginalNavigation. These are reachable stylized local bodies in the same frame as the station and ship.

The core owns a deterministic system-seeded surface recipe and generates bounded elevation/cloud/settlement/scatter maps. These are new procedural art, with periodic longitude, unified polar elevations and seeded cloud/land/city patterns; they do not assert simulated population, actual geography or imported original textures. `WorldAdapter` caches one validated immutable surface for the actual body/recipe. The App now supplies that real scene to `SceneEffects`; title and docked presentation draw no celestial bodies. Root must still merge the final HUD flight viewport/clip with this pass.

`World::step` performs a continuous segment/sphere check against both bodies, expanded by the actual current ship collision mesh's enclosing radius. A contact accepts a safe stop at the prior clear pose, with zero speed, an advanced tick and explicit `CelestialContact` feedback. Rotation is conservatively covered by the enclosing sphere. Endpoint-only tunnelling is rejected. Shared save/load validation rejects player poses inside these expanded surfaces; the refusal has explicit codec value 3. Continue still invalidates old UI review epochs; this is separate from exact physical/celestial state reconstruction. No existing installed profile is migrated or modified by authoring or tests.

Contact currently stops the ship rather than damaging it. Thermal exposure, fuel scooping, gravity, weapon/projectile-versus-celestial occlusion and detailed surface landing are not implemented. The sphere-impostor rendering does not provide collision authority. Current ship radius comes from the same SH025 collision mesh used by station admission; the modular hull join must continue to use the actual selected hull's bound.

The mining dependency is MC1's actual immutable local-belt snapshot: stable system/ordinal body IDs, station-local positions, shared closed convex collision/render mesh, original commodity identity, remaining ore and target/navigation cues. Root and MC1 must supply that exact snapshot for asteroid meshes and target markers. Exhausted rocks retain their real mesh and collision presence. This slice does not create a decorative belt, substitute a sphere for the physical rock mesh or claim a mining hit from a render marker.

## Provenance

[The reference manifest](../assets/legacy/celestial-reference-manifest.json) pins the exact immutable files, source commit and license. The requested shading translation follows `PlanetGPUShader.swift`, `PlanetLighting.swift` and `CelestialRendering.swift`; surrounding palette, terrain and appearance files are references for the required inputs. The retained source has a Stephen Clarke MIT license. That repository-level license alone is not independent proof of every component's original authorship. No external Elite/Oolite shader, texture, model, raster art or font is imported by this slice. The translation retains its source attribution and makes no wider commercial-rights assertion.

## Validation and native acceptance

The complete core suite passed 200 tests after the shared physical/save boundary changed. The desktop celestial suite passed 10 focused tests, and strict workspace Clippy passed. The tests include actual public jump arrival, current-system/visit IDs, pause and cold reconstruction, safe birth geometry for all 256 current navigation records, seeded maps, swept tunnelling and live World-step contact refusal/save restoration. Desktop tests bind generated World data to both visible shader bodies and verify immutable surface reuse, as well as WGSL/Naga validation and uniform offsets.

The first author cold test compared whole encoded save bytes and failed because Continue intentionally increments UI review authority. That failed evidence remains retained. The corrected test checks the unchanged physical snapshot, paused state and exact derived celestial scene. No assertion about byte-identical UI epochs or native acceptance is made.

After the coherent preview join, G1 must compile and launch the exact reviewed candidate on the owned Mac lane. Native checks must observe the same actual body positions while moving and changing camera views; a day/night terminator that follows the actual sun; changing cloud/surface rotation from physical time; atmosphere and cloud-attenuated night emission; sun disc/corona at viewport edges; ship/planet depth ordering; bounded close/interior behavior; and compact/full-screen clipping. The same player journey must locate the real MC1 belt, target an actual rock and mine it through the core command path. A screenshot, synthetic renderer fixture or authored test count cannot replace these checks. Previous profiles and installed previews remain untouched.
