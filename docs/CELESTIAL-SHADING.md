# Planet and sun shading

This renderer slice translates the frozen L337 planet illumination and sun appearance into WGSL/wgpu. It accepts an immutable scene with actual system/visit/body identities, world positions and radii. It creates no default planet, sun or asteroid belt. The simulation remains the only source of physical movement, heat, collisions, mining and navigation state.

The planet shader uses ocean/coast/land, highland, vegetation, polar ice, cloud opacity and drift, surface haze, day/night illumination, atmospheric rim and cloud-attenuated settlement emission. Four interleaved 256 by 128 maps supply elevation, clouds, city emission and nearby settlement scatter. A validated immutable surface owns its palette and maps; a different immutable surface object triggers an upload even if a caller reuses its body identity. The retained GPU cache holds only one surface. It allocates one fixed 512 KiB map buffer and two fixed uniform buffers. It does not allocate a planet-sized framebuffer or synchronously read the GPU each frame.

Lighting comes from the actual planet-to-sun direction after the same camera transform used for the scene. Displayed sphere normals face the viewer, including front, rear and side views. A missing sun produces the source unlit state rather than a decorative fixed light. The sun has the source yellow inner disc, gold outer disc and two orange/gold corona layers. Reference sRGB palette/image colour is converted once for an sRGB render target, including premultiplied halos, to avoid double gamma conversion. Opaque surfaces write depth; premultiplied atmosphere/corona passes test depth without writing it.

The source sphere/frustum intersection and bounded projection retain visible limbs at screen edges and bound near/interior projections. The WGSL sphere is a continuous camera-facing disc at the physical projected radius; the old intermediate bitmap's 0.47 image-padding scale is not copied. Depth is a sphere-impostor approximation, not an exact off-axis raytrace or a collision mesh. This is a deliberate rendering change, not pixel-equivalence evidence.

## Integration contract

`celestial::Scene` carries at most one planet and one sun. Root must supply current system/visit-bound identities, actual world positions/radii, a physical-time-derived planet angle and the actual authored surface palette/maps. Terrain generation and authored system appearance are separate inputs, not guessed in the shader. Foreign system/visit IDs, duplicate body IDs, a mismatched surface identity, nonfinite geometry, invalid projections and malformed maps are rejected. The entire frame is prepared before any upload so an invalid second body cannot publish half a frame.

`SceneEffects` groups current beam, missile, beacon and celestial inputs for the renderer. The author branch's explicit `celestial: None` App hunk marks the missing World provider; it is not playable celestial completion. Root's shared App join must supply the real scene and match the HUD's flight projection/clip. The camera helper is the same `mesh::rotate_inverse` already used by rendered ships. No core, save, Cargo manifest or lock file changes are included.

The mining dependency is MC1's actual immutable local-belt snapshot: stable system/ordinal body IDs, station-local positions, shared closed convex collision/render mesh, original commodity identity, remaining ore and target/navigation cues. Root and MC1 must supply that exact snapshot for asteroid meshes and target markers. Exhausted rocks retain their real mesh and collision presence. This slice does not create a decorative belt, substitute a sphere for the physical rock mesh or claim a mining hit from a render marker.

## Provenance

[The reference manifest](../assets/legacy/celestial-reference-manifest.json) pins the exact immutable files, source commit and license. The requested shading translation follows `PlanetGPUShader.swift`, `PlanetLighting.swift` and `CelestialRendering.swift`; surrounding palette, terrain and appearance files are references for the required inputs. The retained source has a Stephen Clarke MIT license. That repository-level license alone is not independent proof of every component's original authorship. No external Elite/Oolite shader, texture, model, raster art or font is imported by this slice. The translation retains its source attribution and makes no wider commercial-rights assertion.

## Validation and native acceptance

Nine focused tests passed on the author source. They parse and validate the actual WGSL through the current wgpu/Naga frontend, verify the thirteen vec4 uniform offsets, exercise camera/light direction and day/night, test bounded limb/behind/interior projection, validate map/profile inputs and current system/visit identity, and reject a bad second body before frame publication. Strict desktop Clippy passed. These are focused source/shader validation results; no native GPU fragment execution or playable celestial acceptance is claimed.

After the World provider and coherent preview join, G1 must compile and launch the exact reviewed candidate on the owned Mac lane. Native checks must observe the same actual body positions while moving and changing camera views; a day/night terminator that follows the actual sun; changing cloud/surface rotation from physical time; atmosphere and cloud-attenuated night emission; sun disc/corona at viewport edges; ship/planet depth ordering; bounded close/interior behavior; and compact/full-screen clipping. The same player journey must locate the real MC1 belt, target an actual rock and mine it through the core command path. A screenshot, synthetic renderer fixture or authored test count cannot replace these checks. Previous profiles and installed previews remain untouched.
