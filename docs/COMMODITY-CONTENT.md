Cargo and quotes index by native ID. Original display order is `[9,8,10,2,7,12,13,15,14,1,4,5,0,11,6,3,16]`. Sorting the cargo array into this presentation order would change identity. Each ordinary transaction moves one native unit. The source commodity hold rule counts quantity for `t`, and zero commodity hold tonnes for `kg`/`g`; it does not perform fractional SI conversion. Actual mission payloads, reservations, fitted cargo and other physical property still belong in the account's total hold calculation.

Ordinary sellable quantity is `max(0,cargo[index]-markedFirearms(if10)-nativeCaptiveCount(if3)-reservedNavigationTradeCargo(index))`. Navigation reservations can apply to any native ID. Imported Slaves quotes grant no captive/private-sale consent. Ordinary Machinery must remain separate from G02's identified held Machinery. Names, prices and quantities never manufacture custody or permission.

Normal departure applies the original `legal |= cargo[3] + 2*cargo[6] + cargo[10]` to actual held quantities. The three catalogue weights describe that expression. They are not purchase fines or independent per-item bit flags. Cargo, account legality and publication remain World-owned.

## Binary contract

All numbers are little-endian; strings are UTF-8 with byte lengths. Consumers must validate the complete schema and reject truncation, invalid IDs/units/counts, duplicate identities, malformed values and trailing data before publication.

### `commodities.catalogue`

847 bytes, SHA-256 `2dbfb9e0abc0a6c2bad3dbabd9a44942f41a86d55c5c44e885ea3dd2bfbca451`.

Header: eight ASCII bytes `MCOM0001`, then `u16` count 17. Each of the 17 rows, in native ID order, contains:

1. `u8` native ID, `u8` unit tag (`t=0`, `kg=1`, `g=2`), `u8` departure legality weight, `u8` name byte length.
2. Name bytes, then `u8` sector byte length and sector bytes.
3. `f64` basePriceCR, `u64` definition targetStock, `u16` technology, `f64` volatility (26 fixed bytes).

The final 17 bytes are the original display-order IDs. All eight definition fields are retained. The only derived fields are unit tags and the source departure weights.

### `g01-commodities.markets`

1,138 bytes, SHA-256 `8f9ec17f63a8e99a700ec5c01273ca67a8ec1cef42730edc10a8d778f0f1b253`.

Header: eight ASCII bytes `MMKT0002`, then `u16` market count 2 and `u16` commodity count 17. Each market has a `u16` system ID (7, then 185), followed by 17 rows in native ID order. Each row is `u8` ID, `u32` askTenthsCR, `u32` bidTenthsCR, `u64` stock, `u64` quote targetStock and `u64` epoch (33 bytes). Selected epochs are all zero. Quantities are bounded by the source 64-bit `Int.max/17`; credits use integer tenths, with no rounding from basePriceCR.

These are initial seeds. Initialize them once for a new commander. Visits, reloads, reinstall, depletion and rejected actions must not refill stock. Alien Items has definition targetStock 4, but both actual station quotes have stock 0 and quote targetStock 0. Preserve those zeros.

The existing `g01-food.markets` and `station-services-manifest.json` stay byte-for-byte unchanged. Food rows agree exactly: Avenor ask226/bid208/stock128/target126 and Renas ask216/bid196/stock112/target143. G3 must join one canonical Food inventory and stock authority rather than expose both seed formats as independent markets.
