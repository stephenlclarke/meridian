## World authority and units

`World::request_flight_view` owns Front/Rear/Left/Right selection. Desktop must call it when changing the actual rendered view and read `World::flight_view` after Continue; it must not pass a presentation-only front flag to measurement. The core exposes no public sample or reading constructor. `World::publish_step` captures the current endpoint, publishes the ordinary validated simulation/ordnance/navigation result, then observes the new endpoint. Rejected steps and pause cannot supply an interval. Normal simulation can retain a reading in memory; it becomes durable only when the host successfully publishes a save.

The existing station scene already uses centre flight units: position is the same station-local centre coordinate used by its native mesh. SH025 speed units are multiplied by 18 for distance. A step is the actual stored f32 `1/60`, approximately `0.01666666753590107` seconds. Translation is `forward * speed * (1/60) * 18`, approximately 0.30000001564621925 centre units per speed unit per step. No renderer scaling or SI conversion is introduced. A single positive consecutive step is below the original 0.1-second maximum; simulation and physical clocks must both advance by exactly one. The validator reconstructs the same f32 translation from the two retained endpoints.

Both endpoints must be ordinary Flight, front view, speed above zero, in the same post-consent visit/system on the same owned carrier and frozen inventory/equipment revision. Centre distance is inclusively 1000 through 1500. Normalized forward dot station direction must be at least `cos(2 degrees)`; this also gives positive station-relative closing velocity because the admitted station is stationary. The second centre range must decrease and player displacement must exceed `1e-9`. Idle stationary alignment, outward motion, wrong view, wrong fit, jump travel and refused motion do not measure.

Sight uses the actual original station triangles and original missile mesh narrow phase. The issuing station is allowed as nearest contact; its open centre doorway stays open. A nearer distinct missile blocks. Its retained position is checked against the original World-owned launch identity/orientation and bounded travel. Existing T02 beacon geometry, when present during that visit/interval, also blocks according to its actual retained provider geometry. No body is created for this lesson. Saved evidence retains both endpoint body sets; the loader rebuilds the geometric query and validates bounded lifetime/presence, including same-tick command ordering at the final endpoint. This is corruption/consistency checking, not authentication against someone rewriting an entire save.

## Consent, receiving and retained history

`review_flight_reception(action, tick)` supports Accept, Receive and Cancel. A private review binds the exact actual dock, review tick, session epoch and checked material-state fingerprint. The fingerprint includes all saved state except the current simulation tick and its derived envelope checksum; historical permission, reading, dock and terminal clocks remain bound. Ordinary docked redraw ticks may pass before confirmation. Admission still requires the actual current command tick, and a review from the future refuses. Material changes, stale/foreign/post-Continue reviews refuse. `prepare_flight_reception` validates the review again and produces checked candidate bytes plus an exclusive World borrow. The host must atomically publish those bytes before `commit`; dropping the preparation on a writer error leaves live memory unchanged. No filesystem or wall clock enters the core.

Receive requires the retained reading and a newer actual `PhysicalEntry` receipt at the same issuing berth, with the original carrier/owner, visit at least the reading visit and doorway tick strictly after the last endpoint. Neither proximity nor a target label grants entry. Reception remains a separate confirmation after arrival. Complete and cancellation terminal receipts are checked against navigation bounds and later attempt consent chronology, including exact equality when sharing a dock sequence. Rewriting a first trace or an old terminal beyond the next consent refuses atomically.

A completed reception records zero financial settlement and the first `l337.unwritten-route/clue/flight-reception-family-trace`, source `l337.training/flight-reception`, clue `flight-reception-family-trace`. Later completions retain that original trace. T02 and G02 traces are separate and untouched. No cash, fuel, inventory item, missile round, weapon resource or custody ledger is granted, refunded or reset. Ordinary flight/docking still applies its established physics/resource behavior.

A changed inventory/fit revision before measurement blocks measurement even if fitting is later restored. A recorded reading remains valid across subsequent fit changes, as in the original. Changing the carrier or actual fatal player energy ends an active attempt as Failed, with no invented dock or clue. There is no new public hull-switch, repair or damage authority. The authored fatal boundary test deliberately remains an internal reducer fixture and does not qualify a genuine native player hit. Cancel requires the actual issuing berth and original carrier; it retains an Abandoned receipt and permits a new reviewed attempt.

Each supported berth retains at most sixteen T01 records, with one active T01 attempt globally. Shared retained records and active reservations count only the implemented G02, T02 and T01 owners, with original maxima 128 and three. All three acceptance paths and save validation include T01 occupancy; no unimplemented mission occupancy is fabricated.
