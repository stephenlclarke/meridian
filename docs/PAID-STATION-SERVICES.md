## Ownership and exact composition contract

`station_services.rs` contains a dependency-free bounded transaction kernel. `StationMarkets` owns only current market stock, bound to the actual new commander's owner. Its initializer is crate-private and must run once at actual profile birth. It must never be used to recreate stock during a visit, load, depletion, reinstall or command retry. Public `MarketSite`, `FoodQuote`, `Command` and `Event` are descriptive values; no public price, constructor, receipt factory or service fact can authorize a transaction.

`AccountProjection` is a transient read of the actual sole commander account, including owner, hull, account revision, credits, fuel, actual ordinary Food, reserved Food and total used hold. It stores no authoritative wallet or inventory. Total used hold must include G02's identified held Machinery and all other physical cargo. Ordinary Food quantity must come from the account's real commodity property; it must never be inferred from mission tonnes or a UI label. No protected or identified mission unit is transferred by this kernel.

`ServiceFacts` must be projected inside World from its actual current initial berth or physical docking context. Bind the actual owner/hull, galaxy0 system7 or185, main-orbital actor entity1, visit, dock sequence, current epoch and pause state. A selected market site, presentation snapshot, position or caller's Boolean must never create this fact. Root retains the actual World/contact composition; no synthetic test fact is a positive physical authority proof.

`prepare` returns a non-cloneable prospective change without mutating either market or account. `checked_change` consumes that plan and rechecks the complete account projection, complete market state and exact current service facts. Changed fuel, money, cargo, revision, stock, pause or berth makes it stale. Dropping a plan leaves all state unchanged. Prices come only from the imported fixed seeds, never from a command argument. Refill uses actual missing fuel; failed funds, capacity, stock, protected custody and sequence checks refuse before publication.

`CommanderAccount::execute_station_service` now owns that joint mutation. It validates the actual current account, identified freight and retained starter equipment, prepares/checks the service plan, copies the actual account into a local candidate, applies the ordinary debit or source sale result, then revalidates the candidate and its full projection. All checks complete before assigning the candidate account and market together. No fallible call or await follows either assignment. This preserves the actual fit, other property and identified freight rather than rebuilding them from presentation fields. The method accepts a typed service command and current World facts, never a caller balance, arbitrary credit delta or price. Future durable publication must still serialize/publish the whole prospective World before committing; no disk writer or restore factory is implemented here.

The sole account now retains real ordinary `food_tonnes` and `reserved_food_tonnes`, initially zero and changed only by the private service transaction. Existing `other_tonnes` is separate property and is never treated as Food. Shared hold calculation includes ordinary Food, other cargo and every remaining identified G02 tonne. Both ordinary purchase and G02 acceptance use that same92t bound. No public cargo-grant, reservation setter or equipment/fit factory was added. Source ordinary-sale saturation deliberately differs from the G02 reward rule, which still refuses overflow.

## Public World API

| API | Actual behavior |
| --- | --- |
| `World::request_station_service(Command, expected_tick)` | Executes one `BuyFood`, `SellFood` or `RefillFuel` against actual current supported docking admission and the sole account |
| `World::request_refuel(expected_tick)` | Compatibility wrapper over that same shared kernel; returns actual payment, including0 for an already full tank |
| `World::service_snapshot()` | Descriptive ordinary Food/reservation/total hold and actual current station quote; no quote in flight or at an unsupported station |

Service commands take no site, price, DockContext, cargo quantity or fit argument. World derives the site only from its genuine current galaxy0 Avenor/Renas `DockContext`, plus actual owner, hull, station actor, visit, dock sequence, current session epoch and pause state. Stale ticks, prototype worlds, airborne/launching states, pause and unsupported original systems refuse. The actor/contact is not a separate shop wallet; ordinary services need the actual berth, while G02 still needs explicit NPC contact/review/confirmation. Account revision changes invalidate earlier freight reviews. Market state is initialized once at fresh profile creation and retained through launch, travel, receiving and return.
